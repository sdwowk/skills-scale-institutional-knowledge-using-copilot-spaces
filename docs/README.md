# OctoAcme Project Management Docs

This README is the central index for OctoAcme project management documentation.

## Project Management Process Summary

OctoAcme uses a lightweight, iterative project lifecycle. Teams initiate projects by agreeing on the problem, goals, stakeholders, and risks, then plan scope, milestones, dependencies, and a prioritized backlog. During execution, teams deliver in small increments and track work on a project board, progressing through review and QA before marking work done. Releases are validated, deployed, and verified, with outcomes and lessons carried into retrospectives and continuous improvement.

The Project Manager coordinates plans, schedules, risks, dependencies, and communications; the Product Manager defines outcomes, prioritizes work, and measures impact. Developers implement and test work, QA validates acceptance criteria and quality, and stakeholders provide input and approvals. Clear ownership supports collaboration across the project lifecycle.

Teams communicate through regular standups, weekly delivery and PM/Product alignment, milestone demos, and monthly stakeholder updates, with risks and blockers escalated through defined paths. Quality is supported by acceptance criteria and a Definition of Done, small reviewed pull requests, automated tests and linting in CI, security scanning, and appropriate integration, end-to-end, and manual QA before release.
